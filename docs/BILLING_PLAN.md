## 3. หน้าจอ

### 3.1 "แพ็กเกจและการชำระเงิน" (เจ้าของแบรนด์เท่านั้น)
เข้าจากเมนูข้าง (กลุ่ม "ตั้งค่าร้าน" → **แพ็กเกจและการชำระเงิน**) และจากแถบเตือนทุกจุด · ใช้ layout เดียวกับแดชบอร์ด (`merchant-layout`) แทนหน้า `/dashboard/wallet` เดิม (ลิงก์เดิม redirect มา)

```
┌ แพ็กเกจปัจจุบัน ─────────────────────────┐ ┌ กระเป๋าเงิน ──────────────┐
│ โปร · ต่ออายุ 8 ธ.ค. 2569 (อีก 30 วัน)    │ │ 1,250 บาท                  │
│ [●] ต่ออายุอัตโนมัติจากกระเป๋า            │ │ พอต่อโปรได้อีก 1 เดือน       │
│ ใช้ไป: จอง 132 · ข้อความ 1,240/4,000 ▓▓░░ │ │ [ เติมเงิน ]               │
│ ตรวจสลิป 41/300 · ช่าง 4/∞ · สาขา 1/2      │ └───────────────────────────┘
└──────────────────────────────────────────┘
[ รายเดือน | รายปี (ประหยัด 2 เดือน) ]
┌ ฟรี ┐ ┌ เริ่มต้น ┐ ┌ โปร ★ปัจจุบัน ┐ ┌ สมาชิก ┐   ← การ์ดเทียบ + ปุ่ม อัปเกรด/ลดแพ็กเกจ
แพ็กเสริม: ข้อความ · ตรวจสลิป · สาขาเพิ่ม · SMS · ตั้งค่าร้านให้   ← การ์ดเล็ก + ปุ่มซื้อ
ประวัติ: เติมเงิน / ซื้อ / ต่ออายุ / คืนเงิน · [ใบเสร็จ]
```

### 3.2 เติมเงิน (แผงเลื่อนจากขวา แบบ `EditorSheet`)
1. เลือกยอด (500 / 1,000 / 3,000 / กรอกเอง 100–20,000) — แนะนำยอดที่ "พอสำหรับแพ็กเกจที่เลือก"
2. **QR พร้อมเพย์ใส่ยอดแล้ว** (`promptPayQr` ของบัญชี Kiwmee จาก `billing.promptpay`) + เลขบัญชี/ชื่อบัญชี + ปุ่มคัดลอก + ปุ่มบันทึก QR (มือถือ)
3. ลาก/เลือกรูปสลิป (ช่องแบบเดียวกับตัวแก้รูป) → ตรวจ → ผล:
   - ผ่าน: "เติม 1,000 บาทแล้ว · ยอดใหม่ 2,250" + ถ้ามีรายการรอซื้อ ถามต่อ "ซื้อโปรเลยไหม"
   - ไม่ผ่าน: เหตุผลภาษาคน (ยอดไม่ครบ / โอนผิดบัญชี / สลิปซ้ำ / เก่าเกิน 7 วัน) + "ส่งให้ทีมงานตรวจ" (เป็น pending เดิม)

### 3.3 ซื้อ/เปลี่ยนแพ็กเกจ
- กดอัปเกรด → แผงยืนยัน: ราคา, **ส่วนต่างที่ต้องจ่ายวันนี้** (ข้อ 5.2), วันต่ออายุใหม่, ยอดกระเป๋าหลังซื้อ → ถ้าเงินไม่พอ ปุ่มกลายเป็น "เติมเงิน X บาท" (ยอดขาดพอดี)
- ลดแพ็กเกจ → "มีผลวันที่ 8 ธ.ค." + รายการสิ่งที่จะถูกพัก (เช่น "ระบบสมาชิกจะหยุดสะสม", "ช่าง 2 คนเกินสิทธิ์จะรับจองไม่ได้") + ยกเลิกการลดได้ก่อนถึงวัน

### 3.4 เตือนในแดชบอร์ด (แถบบนสุดของทุกหน้า)
| เมื่อ | ข้อความ |
|---|---|
| ใช้ ≥ 80% ของจอง/ข้อความ/สลิป | "ข้อความ LINE ใช้ไป 85% · ซื้อเพิ่ม" |
| แพ็กเกจเหลือ ≤ 7 วัน และเงินไม่พอต่อ | "แพ็กเกจโปรหมด 15 พ.ย. · เติมเงินอีก 340 บาทเพื่อต่ออัตโนมัติ" |
| อยู่ในช่วงผ่อนผัน | "แพ็กเกจหมดแล้ว · ใช้งานต่อได้ถึง 22 พ.ย. แล้วจะกลับเป็นแพ็กเกจฟรี" |
| กดใช้ฟีเจอร์ที่แพ็กเกจไม่ถึง | การ์ดล็อก 🔒 "ใช้ได้ในแพ็กเกจโปร · ดูแพ็กเกจ" (แทนฟอร์ม) |

### 3.5 หน้าจองลูกค้า
- แพ็กเกจฟรีจองครบ 50 ครั้งในเดือน → ลูกค้าเห็น "ร้านปิดรับจองออนไลน์ชั่วคราว · โทร 0xx" (ไม่บอกว่าร้านไม่จ่ายเงิน) · ร้านยังเพิ่มการจองเองในแดชบอร์ดได้
- แพ็กเกจ `loyalty` ไม่มีหน้าจอง → `/b/<slug>` แสดงบัตรสมาชิก/ข้อมูลร้านอย่างเดียว

### 3.6 `/super`
- ตั้งแพ็กเกจให้แบรนด์เอง (ไม่ต้องใช้ SQL): แพ็กเกจ · วันหมดอายุ · เหตุผล (บันทึกใน log)
- ให้เครดิต/ปรับยอดกระเป๋า (`kind = adjust` พร้อมเหตุผล) · ให้ทดลองใช้
- รายการแบรนด์ที่ใกล้หมดอายุ / อยู่ในช่วงผ่อนผัน / ใช้เกินโควตา

## 5. กติกาเงิน (รายละเอียดสำหรับ B4)

### 5.1 ซื้อ/ต่ออายุแพ็กเกจเดิม
ต่อจาก `valid_until` เดิม (ถ้ายังไม่หมด) หรือจากวันนี้ (ถ้าหมดแล้ว) · รายเดือน = +30 วัน · รายปี = +365 วัน

### 5.2 อัปเกรดกลางรอบ (มีผลทันที)
`จ่ายวันนี้ = (ราคาใหม่ − ราคาเดิม) × วันที่เหลือ / วันในรอบ` ปัดขึ้นเป็นบาท · วันหมดอายุเท่าเดิม
ตัวอย่าง: เริ่มต้น → โปร เหลือ 12 จาก 30 วัน = (890−390) × 12/30 = **200 บาท**
รายเดือน → รายปี: จ่ายราคารายปีเต็ม หักมูลค่าวันที่เหลือของรายเดือน · เริ่มรอบปีวันนี้

### 5.3 ลดแพ็กเกจ
ตั้ง `next_plan` · มีผลตอนต่ออายุครั้งถัดไป · ไม่คืนเงินส่วนที่เหลือ · ยกเลิกได้ก่อนถึงวัน · เลือก "ฟรี" = ปิดต่ออายุอัตโนมัติ

### 5.4 ต่ออายุอัตโนมัติ (ปรับ `renewDuePlans`)
เหลือ ≤ 3 วัน + `auto_renew` + เงินพอ → ตัดและต่อ (ใช้ `next_plan` ถ้ามี) · เงินไม่พอ → ไม่ตัด, เตือน · ถึงวันหมดแล้วยังไม่พอ → `grace_until = valid_until + 7 วัน` (ใช้งานเหมือนเดิม) · พ้นช่วงผ่อนผัน → `free` (ข้อมูลอยู่ครบ) · เติมเงินระหว่างผ่อนผัน → ต่ออัตโนมัติทันที

### 5.5 ทดลองใช้
แบรนด์ใหม่ได้ `pro` + `trial_until = +14 วัน` ครั้งเดียวต่อเจ้าของ (กันสมัครใหม่วนซ้ำด้วย user id) · ไม่ตัดเงิน · ครบแล้ว → free (หรือแพ็กเกจที่ซื้อไว้)

### 5.6 สิ่งที่ "พัก" เมื่อแพ็กเกจลดลง
| ของที่เกิน | ผล |
|---|---|
| ช่าง/สนามเกินจำนวน | ตัวที่เปิดล่าสุดถูกปิดรับจองออนไลน์ (เจ้าของเลือกเองได้ว่าจะเปิดตัวไหน) · การจองที่มีอยู่ไม่ถูกยกเลิก |
| สมาชิกทีมเกิน | เข้าแดชบอร์ดได้แบบอ่านอย่างเดียว จนเจ้าของเอาออก/อัปเกรด |
| สาขาเกิน | สาขาที่เกินปิดรับจองออนไลน์ (ข้อมูลอยู่) |
| ระบบสมาชิก | หยุดสะสม/แลก · คะแนนเดิมไม่หมดอายุระหว่างพัก (เลื่อนวันหมดอายุออกไปตามช่วงที่พัก) · บัตรขึ้น "พักชั่วคราว" |
| ผัง/เช่ารายวัน/ตัวเลือกเสริม | ลูกค้าเห็นเป็นรายการธรรมดา / จองแบบรายวันไม่ได้ / ไม่เห็นตัวเลือกเสริม · การตั้งค่าเก็บไว้ |

## 6. ต้องให้เจ้าของตัดสินก่อนเริ่ม

1. **ราคาและตัวเลขในข้อ 2** ยืนยัน/แก้ (โดยเฉพาะ: ข้อความโปร 4,000 vs 3,000 · สาขาเพิ่ม 290 · ฟรี 50 การจอง)
2. **ร้านที่ใช้อยู่ตอนนี้** (ทุกร้านเป็น free และใช้ได้ทุกฟีเจอร์) — ตอน B3 ขึ้นจะทำอย่างไร
   - (แนะนำ) ให้ทุกแบรนด์ที่มีอยู่เป็น **โปรฟรีถึง 31 ม.ค. 2570** แล้วค่อยเลือกแพ็กเกจ · แจ้งในแดชบอร์ดล่วงหน้า
   - หรือ ใช้แพ็กเกจฟรีทันที
3. **ภาษี/ใบเสร็จ** Kiwmee จด VAT หรือยัง · ออก "ใบเสร็จรับเงิน" หรือ "ใบกำกับภาษี" · VAT คิดตอนเติมเงินหรือตอนซื้อแพ็กเกจ (ให้นักบัญชียืนยัน) · ชื่อ/ที่อยู่/เลขผู้เสียภาษีของ Kiwmee บนใบเสร็จ
4. **SMS** จะใช้ผู้ให้บริการไหน (เช่น ThaiBulkSMS / SMSMKT) — ถ้ายังไม่เลือก B6 ทำแค่สาขาเพิ่ม + บริการตั้งค่า
5. **แจ้งเตือนเจ้าของร้าน** ทางไหน: อีเมล (บัญชีที่ล็อกอิน) · LINE (ต้องให้เจ้าของผูก LINE กับบัญชีก่อน) · ทั้งคู่
6. **คืนเงินจากกระเป๋า** ทำไหม (ตอนนี้: ไม่คืน ไม่หมดอายุ — ต้องเขียนใน `/terms`)
7. **ชื่อแพ็กเกจที่ร้านเห็น**: ฟรี / เริ่มต้น / โปร / สมาชิก หรือชื่ออื่น

## 7. การทดสอบที่ต้องมี (ทุก PR)

- unit: ตารางแพ็กเกจ JS ตรงกับ `plan_limit()` ใน SQL · คำนวณส่วนต่าง/รายปี/ผ่อนผัน/ทดลองใช้ทุกกรณี (ปัดเศษ, วันสุดท้าย, เดือน 28–31 วัน)
