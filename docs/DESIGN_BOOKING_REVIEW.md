## 1. สรุปคำตัดสิน

**ดีไซน์ใช้งานได้จริงและสวย — นำไปทำได้เลย ~80%** แต่มี **5 จุดที่ขัดกันเองในดีไซน์** และ **6 ฟีเจอร์ที่ระบบยังไม่มี** ต้องตัดสินใจก่อนเริ่มเขียนโค้ด

| ด้าน | คะแนน | หมายเหตุ |
|---|---|---|
| ความสวย/แบรนด์ | ดีมาก | สี ม่วง/มินต์ ตรงแบรนด์, ใช้ Anuphan, ระยะห่างดี |
| การใช้งานบนมือถือ | ดี | sticky bar + stepper ชัด, แต่มีตัวอักษร 10–11px และชิป 32px |
| ความเป็นไปได้กับระบบจริง | ปานกลาง | บางหน้าจอสมมติฟีเจอร์ที่ยังไม่มี (หลายบริการ, คูปอง, รีวิว, LINE Pay) |
| ความสอดคล้องภายใน | ต้องแก้ | เงื่อนไขการชำระเงิน/ยกเลิก/VAT ขัดกันเอง |

## 3. ฟีเจอร์ในดีไซน์ vs ระบบจริง

| ดีไซน์ | ระบบตอนนี้ | งานที่ต้องเพิ่ม |
|---|---|---|
| เลือก **หลายบริการ** ต่อการจอง | 1 การจอง = 1 บริการ | `booking_services` + เวลาต่อเนื่อง + ราคารวม (งานใหญ่ 2–3 PR) |
| **Combo package** | ❌ | ตาราง combo + ราคา/เวลาเหมารวม |
| **คูปอง/Voucher** | ❌ | `vouchers` + ผูกการจอง + ตรวจสิทธิ์ |
| **รีวิว/ให้ดาว** | ❌ | `reviews` + ผูก LINE userId + กันรีวิวซ้ำ |
| **มัดจำออนไลน์ LINE Pay** | ❌ (มีสลิป/EasySlip) | สมัคร Rabbit LINE Pay + webhook |
| **บันทึกปฏิทิน .ics** | ❌ | endpoint เดียว — งานเล็ก ทำได้เลย |
| QR เช็คอิน | ✅ มี | ใช้ได้เลย |
| แต้ม/ระดับสมาชิก | ✅ มี | ใช้ได้เลย |
| มัดจำ + แนบสลิป | ✅ มีบางส่วน | ต่อ UI เข้าไป |

## 4. จุดที่ควรแก้ด้าน UX/UI (แก้ไว)

1. หัวเรื่องภาษาอังกฤษปนไทย (Service Selection / Staff And Slot / Booking Confirmation / My Bookings / Services Catalog) → ไทยล้วน
2. ข้อความขั้นตอนไม่สม่ำเสมอ ("ขั้นตอนที่ 1 จาก 4" vs "ขั้นตอน 2 / 4")
3. `user-scalable=no, maximum-scale=1.0` ในทุกไฟล์ → **ห้ามผู้ใช้ซูม** ควรเอาออก
4. ตัวอักษร 10–11px ("ถึง 12:15", "2 รายการ • ฿1,950") → ≥12px
5. ชิปตัวกรองสูง ~32px → ≥44px
6. `...` → `…` · ชื่อบริการอังกฤษตัดคำกลางคำ → `line-clamp-2` + `text-pretty`
7. วันอาทิตย์ตัวแดงแต่ไม่บอก "ปิด" → เพิ่มข้อความ (ไม่ใช้สีอย่างเดียว)
8. คำผิด: "คิวแนวะนำ"→คิวแนะนำ · "ช่างได้ก็ได้"→ช่างไหนก็ได้ · "ดิจิตอลล็อค"→ดิจิทัล · "เวลไม่พอต่อเนื้อเรื่อง"→เวลาที่เหลือไม่พอ
9. ยังไม่มี state: **ไม่มีคิวว่าง / ร้านปิด / บริการปิดรับ / คิวถูกจองตัดหน้า / loading**
10. PDPA: มีแค่ลิงก์เงื่อนไข ควรมีนโยบายความเป็นส่วนตัว (`/privacy` มีแล้ว)
11. Screenshot step 2 ถูกตัดที่ 1105px (time grid ไม่ติดมา) — ตัว HTML ครบ
12. mock ไม่ตรงกัน: "26 มี.ค. 2025" vs "26 มีนาคม 2568" → ใช้ พ.ศ. ให้เหมือนกัน

## 6. คำถามรอคำตอบ (4 ข้อ) เพื่อเริ่มเฟส 1

1. **มัดจำ**: ไม่เก็บ / โอน+แนบสลิป / LINE Pay
2. **VAT**: ร้านจด VAT หรือไม่ (ถ้าไม่จด = เอาข้อความออก)
3. **หลายบริการ**: ต้องมีตั้งแต่เฟส 1 ไหม (ถ้าใช่ เฟส 1 ยาวขึ้น ~2 เท่า)
4. **ชำระหน้าร้าน**: ยืนยันแล้วจ่ายที่ร้านเลยใช่ไหม
