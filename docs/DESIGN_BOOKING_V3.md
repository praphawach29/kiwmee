## 1. คำตัดสินใจของเจ้าของ (6 พ.ย. 2569) — ล็อกแล้ว

| เรื่อง | ข้อสรุป |
|---|---|
| **มัดจำ** | เฟส 1 รองรับ 2 แบบ: **ไม่เก็บมัดจำ** (ชำระหน้าร้าน 100%) และ **โอนมัดจำ + แนบสลิป** (ตรวจด้วย EasySlip) · **ไม่ทำ LINE Pay** |
| **VAT** | **ไม่แสดงข้อความ/บรรทัด VAT** — โชว์ราคาสุทธิ (ร้านขนาดเล็กส่วนใหญ่ไม่จด VAT) |
| **หลายบริการ** | เฟส 1 = **1 บริการหลัก + add-ons** (ระบบรองรับอยู่แล้ว) · เฟส 2 ค่อยทำ Multi-Service Cart |
| **ชำระหน้าร้าน** | กด "ยืนยันการจอง" = **ล็อคคิวทันที** (ไม่มีมัดจำ) แล้วไปจ่ายที่ร้านหลังรับบริการ |

ผลต่อดีไซน์ที่ต้องแก้ทันที: เอา "รวมภาษีมูลค่าเพิ่ม 7%" ออก · เอา SMS ออก (ใช้ LINE) · เอา LINE ID ซ้ำซ้อนออก · เลือกข้อความยกเลิกค่าเดียว (ใช้ค่าจากการตั้งค่าร้าน) · ไม่มีปุ่ม LINE Pay

## 2. ขอบเขตเฟส 1

**อยู่ในเฟส 1**
- หน้าจอง 4 ขั้น (เลือกบริการ → ช่าง/วัน/เวลา → ข้อมูล+สรุป → สำเร็จ) ตามดีไซน์
- 1 บริการ + add-ons (จำนวนชิ้นได้)
- มัดจำ: `none` (default) หรือ `fixed/percent/full` + อัปโหลดสลิป + EasySlip ตรวจอัตโนมัติ
- หน้าสำเร็จ: เลขจอง, QR เช็คอิน, **เพิ่มในปฏิทิน (.ics)**, แชร์ LINE, ลิงก์จัดการนัด
- คิวของฉัน / เลื่อนนัด / ยกเลิก (มีอยู่แล้ว — ปรับหน้าตา)
- ราคาสุทธิ (ไม่มี VAT) + แสดงนโยบายยกเลิกจากค่าตั้งร้าน

**ยังไม่อยู่ในเฟส 1**
- Multi-service cart, combo package (เฟส 2)
- คูปอง/voucher, รีวิว (เฟส 3)
- LINE Pay / บัตรเครดิต

## 4. API/ข้อมูลที่ใช้ซ้ำ (ไม่ต้อง migration ใหม่ในเฟส 1)

| ความต้องการ | ของเดิม |
|---|---|
| ข้อมูลร้าน/บริการ/ช่าง/แอดออน/มัดจำ | `GET /api/b/[slug]` → `shopInfo()` (`src/v2/public-booking.js`) มี `deposit: {mode,value,holdMinutes}` อยู่แล้ว (`none·fixed·percent·full`) |
| คิวว่าง | `POST /api/b/[slug]/step` (askable: offering·resource·date·time·duration·party·addons) |
| สร้างการจอง | `POST /api/b/[slug]/bookings` |
| อัปสลิปมัดจำ | `POST /api/b/[slug]/manage/[token]/slip` + EasySlip (`slip-check.js`, มี `recordSlipCheck` นับโควตา) |
| เลื่อน/ยกเลิก | `POST …/manage/[token]/reschedule` · `…/cancel` |
| คิวของฉัน | `GET /api/b/[slug]/me` (+ `me/code`, `me/rewards`) |
| QR เช็คอิน | `GET /api/b/[slug]/checkin-qr/[id]` |
| นโยบายยกเลิก | `business_booking_settings` (ใช้ค่าเดียวกันทุกหน้า) |

**งาน backend ใหม่เล็ก ๆ ในเฟส 1:** `GET /api/b/[slug]/bookings/[id]/calendar.ics` (สร้างไฟล์ ICS จาก booking + token) — ไม่ต้องมีตารางใหม่

## 6. Must-fix UX (จากผลตรวจ) — ต้องแก้ใน v3-1 เป็นอย่างช้า

1. หัวเรื่องเป็นไทยทั้งหมด (ไม่ใช้ Service Selection / Staff And Slot / Booking Confirmation)
2. ข้อความขั้นตอนรูปแบบเดียว: "ขั้นตอนที่ N จาก 4"
3. ไม่ใช้ `user-scalable=no` / `maximum-scale=1`
4. ตัวอักษรขั้นต่ำ 12px (ป้าย 10–11px ต้องโตขึ้น) · ชิป/ปุ่ม ≥44px
5. `…` แทน `...` · ชื่อยาวใช้ `line-clamp-2` + `text-pretty`
6. สถานะวันปิดต้องมีคำ ("ปิด") ไม่ใช้สีแดงอย่างเดียว
7. แก้คำผิด: คิวแนะนำ · ช่างไหนก็ได้ · ดิจิทัล · "เวลาที่เหลือไม่พอสำหรับบริการนี้"
8. State ครบ: ไม่มีคิวว่าง / ร้านปิด / บริการปิดรับ / **คิวถูกจองตัดหน้า** / loading skeleton
9. ลิงก์นโยบายความเป็นส่วนตัว (`/privacy`) ในหน้าข้อมูลผู้จอง + ข้อความยินยอม
10. ตัวเลข/วันที่ใช้ `Intl` (พ.ศ. สม่ำเสมอ), ราคาใช้ `Intl.NumberFormat("th-TH")`

## 7. Test plan (เฟส 1)

- unit: คำนวณราคาสุทธิ (ไม่มี VAT), มัดจำ `none/fixed/percent/full`, add-ons รวมราคา, ICS payload
- DB test: จองแบบไม่เก็บมัดจำ → คิวถูกล็อค (`booking_resources`), จองซ้ำเวลาเดียวกันไม่ได้
- DB test: มัดจำ → booking `pending_payment` จนสลิปผ่าน
- manual: มือถือ 390px ครบ 4 ขั้น, กดย้อนกลับทุกขั้น, คิวถูกตัดหน้า, เน็ตช้า (skeleton)
