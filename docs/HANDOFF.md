# Kiwmee — สรุปสถานะสำหรับ session ถัดไป

ปรับล่าสุด: 2 พ.ย. 2569 · อ่านคู่กับ `CLAUDE.md` (กติกาการทำงาน) และ `docs/SALES_READINESS_ROADMAP.md` (แผนสู่การขายจริง)

**Kiwmee** = ระบบจองคิวหลายร้านผ่านเว็บ/LINE ที่กำลังต่อยอดเป็น**ระบบสมาชิก + คะแนนสะสม** ในผลิตภัณฑ์เดียว
Next.js 15 + Supabase · deploy บน Railway service `salon-booking-os-v1` → `https://kiwmee.up.railway.app` ทุกครั้งที่ merge เข้า `main`

**Repo เปลี่ยนชื่อเป็น `praphawach29/kiwmee`** (เดิม `salon-booking-os-v1`, GitHub redirect ลิงก์เก่าให้) · ชื่อ service บน Railway และโดเมนยังเป็นชื่อเดิม ·
ถ้า Railway ไม่ deploy หลัง merge ให้เชื่อม repo ใหม่ที่ Railway → service → Settings → Source

- ระบบสมาชิก (คะแนน, ระดับ, บัตร) = **แพ็กเกจเสียเงิน** · ตัวเลขราคายังไม่ได้ตั้ง
- คู่แข่ง: LINE MyCustomer ฟรีในแพ็กเกจ LINE OA Pro (1,780 บาท) · Privage (รายปี + SMS OTP) → ราคาโปรไม่ควรสูงกว่า LINE Pro มาก

**ตั้ง LIFF (ทดสอบจองผ่าน LINE)** — LIFF ID `2010969802-QiiDBSxa` (เลขหน้าขีด = Channel ID ของ LINE Login channel)
- LINE Developers → LINE Login channel → LIFF → Endpoint URL `https://kiwmee.up.railway.app/b` · Size Full · Scopes `openid` + `profile`
- `/super` → LIFF ID + LINE Login · Channel ID (ไม่ใส่ Channel ID = การจองจาก LINE ถูกปฏิเสธ "ยืนยันตัวตน LINE ไม่สำเร็จ")
- channel สถานะ Developing ใช้ได้เฉพาะ admin/tester ของ channel · เปิดให้ลูกค้าจริงต้อง Publish

- ลูกค้ายืนยันตัวตนด้วย **LINE อย่างเดียว** (ไม่ทำ OTP) · คนเดียวกันข้ามร้าน = `line_user_id` เดียวกัน
- **เริ่มด้วย LINE OA กลางของ Kiwmee** ส่งการ์ดยืนยัน/เตือนนัด/เตือนคะแนนหมดอายุของทุกร้าน (ร้านใช้ OA ตัวเองเป็นตัวเลือกภายหลัง)
- ทุก channel (LINE Login, LIFF, Messaging API) ต้องอยู่ใต้ **LINE provider เดียวกัน** ไม่งั้น userId ไม่ตรงกัน
- ราคา LINE OA (มีผล 1 ส.ค. 2567): Free 300 ข้อความ · Basic 1,280 บาท/15,000 · Pro 1,780 บาท/35,000

**แบรนด์และสาขา**
- สาขา = `businesses` แต่ละแถว อยู่ใต้ **แบรนด์** (`brands`) · คะแนนใช้ได้ทุกสาขาของแบรนด์
- **เจ้าของแบรนด์**เท่านั้นที่ตั้งกติกา/รางวัล/แจกคะแนนเอง · กำหนดได้ว่ารางวัลใช้ทุกสาขาหรือเฉพาะสาขา

**บิลและคะแนน**
- **บิลแยกจากการจอง** (บิลผูกการจองหรือไม่ก็ได้) → ร้านที่ไม่รับจอง (เช่นร้านก๋วยเตี๋ยว) ใช้ระบบสมาชิกได้
- **ได้คะแนนตอนปิดบิล** จากยอดที่จ่ายจริงหลังหักส่วนลด · **ปัดเศษทิ้ง** · มัดจำ/ยกเลิก/ไม่มา ไม่ได้คะแนน
- คืนเงิน → ดึงคะแนนคืนตามสัดส่วน · รางวัลที่แลกแล้วไม่คืนอัตโนมัติ
- ร้านตั้งกติกาเอง: ต่อยอดเงินหรือต่อครั้ง · รางวัลเป็นส่วนลดหรือใช้บริการฟรี · **ใช้ได้ทีละ 1 รางวัลต่อบิล** · คะแนนที่เหลือเก็บต่อ
- รางวัลเป็นการ์ดคูปองมีรูป จำนวนสิทธิ์ จำกัดต่อคน และช่วงแคมเปญ
- คะแนน**มีวันหมดอายุ** ร้านตั้งเอง · เตือนทาง LINE 14 วันก่อน · ใช้ล็อตที่หมดอายุก่อน (FIFO)
- **ระดับสมาชิก** คิดจากยอดบิลย้อนหลัง (ไม่ใช่คะแนน) · ไม่เกิน 5 ระดับ · ตัวคูณคะแนนและรางวัลเฉพาะระดับ · บัตรสวยตามระดับ
- QR สมาชิกเป็นรหัสชั่วคราว 60 วินาที (กันแคปหน้าจอ)

**ระบบจองเดิม**: นโยบายยกเลิก/เลื่อนตั้งต่อร้าน (เปิด/ปิดแยกกัน + กี่ชั่วโมงก่อนนัด, ค่าเริ่มต้น 2 ชม.)

6. โค้ด v1 ยังอยู่ใน repo (`/admin`, `/manage`, `src/` เดิม) — เก็บกวาดหลังย้าย LINE/ชำระเงินมา v2 (Phase 5)

## 5. เตรียมเครื่อง cloud ใหม่

```bash
npm ci && npm test                          # ผ่านหมด มีเทสต์ที่ถูกข้ามเพราะต้องใช้ DB
```

**Postgres ทดสอบ** (เครื่อง cloud มี Postgres 16 + `btree_gist` + `psql` อยู่แล้ว ไม่ต้องติดตั้ง):

```bash
D=/var/lib/postgresql/kiwmee-test
mkdir -p $D && chown postgres $D && chmod 700 $D
[ -f $D/PG_VERSION ] || su postgres -c "/usr/lib/postgresql/16/bin/initdb -D $D -U postgres --auth=trust -E UTF8"
su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D $D -o '-p 54329 -k /tmp' -l $D/log start"
SUPABASE_TEST_DB_URL=postgres://postgres@127.0.0.1:54329/booking_test npm run test:db   # ล่าสุด 87/87
```
- อย่าเก็บ data dir ไว้ใน scratchpad (`/tmp/claude-0/...`) — สิทธิ์โฟลเดอร์ถูกรีเซ็ตแล้ว Postgres เปิดไม่ได้
- เครื่องรีสตาร์ตแล้ว server หยุด ต้องสั่ง `pg_ctl … start` ใหม่

**Playwright** (หน้าจองจริงกับ DB ทดสอบ):

```bash
npx next build && BOOKING_DB_URL=postgres://postgres@127.0.0.1:54329/booking_test BOOKING_BOOK_LIMIT=100 SUPABASE_URL=https://example.supabase.co SUPABASE_PUBLISHABLE_KEY=test npx next start -p 3100   # รันค้างไว้ (next dev พังที่ /dashboard — ดู §4)
PILOT_BASE_URL=http://127.0.0.1:3100 PW_EXECUTABLE=$(ls -d /opt/pw-browsers/chromium-*/chrome-linux*/chrome | head -1) \
  npx playwright test e2e/booking-v2.spec.cjs                                                                  # ล่าสุด 8/8
```
- โหมด dev คอมไพล์ช้า: กดปุ่มก่อนหน้า hydrate จะไม่ตอบสนอง → ใช้ `waitForLoadState("networkidle")`
- ห้าม format วันที่ด้วย `weekday: "short"` ในสิ่งที่ render ฝั่งเซิร์ฟเวอร์ (Node กับเบราว์เซอร์ให้ชื่อย่อต่างกัน → hydration mismatch) · หน้าจองใช้ตาราง `SHORT_DAYS` ของตัวเอง
- เทสต์ e2e ซ้ำหลายรอบ คิวใน DB ทดสอบจะเต็ม → `npm run test:db` สร้าง DB ใหม่

**แอดมิน `/dashboard`** ต้องใช้ Supabase Auth จริง ล็อกอินในเครื่อง cloud ไม่ได้ → ดูหน้าจอจริงได้โดยเปิด `next dev` แล้วใช้ Playwright
`page.route("**/api/dashboard/shops/**")` ตอบด้วยฟังก์ชันจริงใน `src/v2/admin-*.js` ที่รันกับ DB ทดสอบในฐานะเจ้าของร้าน
(`admin.actAs(db, user)` ใน transaction) — วิธีที่ใช้ตรวจหน้าบิล (PR #15) และหน้าแบรนด์ (PR #16)
**ต้องเข้าคิวทีละคำขอ** (หน้าเว็บยิงหลายคำขอพร้อมกัน แต่ pg client เดียวมี transaction ได้ทีละอัน) · หน้า `/dashboard` ต้องตั้ง
`SUPABASE_URL`/`SUPABASE_PUBLISHABLE_KEY` ปลอมตอน `next dev` และตอบ `/api/dashboard/session` ด้วย `{ data: { user } }`

**Git**: branch ของ session มักถูก squash merge ไปแล้ว · ห้าม force push (ถูกปฏิเสธ) →
`git checkout -B <branch> origin/main` แล้ว `git merge -s ours origin/<branch>` ก่อน push

**เครือข่าย**: เว็บภายนอกบางโดเมน (privageapp.com, lineforbusiness.com, fresha.com) เปิดตรงไม่ได้ → ใช้ WebSearch แทน
