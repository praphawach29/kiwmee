# กระเป๋าเงินร้านค้า + การเติมเงินอัตโนมัติ (migration …003700)

## ทำไมต้องมี

ยังสมัคร Omise ไม่ได้ จึงยังรับบัตรไม่ได้ ร้านจึงจ่ายด้วย **การโอนเงิน + แนบสลิป** เงินที่โอนเข้าอยู่ใน **กระเป๋าของแบรนด์** แล้วเอาไปซื้อแพ็กเกจ/แพ็กเสริมได้ทันที ไม่ต้องรอผู้ดูแลตรวจทีละใบ

## กติกาที่ระบบบังคับ (server เท่านั้นที่เขียนกระเป๋าได้)

| กติกา | รายละเอียด |
|---|---|
| เติมขั้นต่ำ–สูงสุด | 100–20,000 บาท ต่อครั้ง (จำนวนเต็ม) |
| สลิปผ่านเมื่อ | EasySlip อ่านได้ · ยอด ≥ ที่ขอ · ผู้รับคือบัญชี Kiwmee (พร้อมเพย์/เลขบัญชีใน `/super`) · ไม่ใช่สลิปซ้ำ (`trans_ref` ไม่ซ้ำทั้งระบบ) · โอนภายใน 7 วัน และไม่เกิน 10 นาทีในอนาคต |
| เติมเข้าอัตโนมัติ | ผ่านทุกข้อ → เข้ากระเป๋าทันทีในคำขอเดียวกัน (ยอดที่เข้าคือยอดบนสลิป — โอนเกินได้ เกินเข้า) |
| ไม่ผ่าน | เก็บเป็น `pending` พร้อมเหตุผล (เช่น `AMOUNT_LOW`, `RECEIVER_MISMATCH`, `DUPLICATE`, `TOO_OLD`) ให้ผู้ดูแลตรวจ — ไม่ตัดเงิน ไม่เติมเงิน |
| ยังไม่ตั้งคีย์ EasySlip | ทุกใบเป็น `pending` (ไม่มีการตรวจ) — ระบบยังใช้งานได้ แต่ไม่มีอะไรอัตโนมัติ |
| ซื้อของ | ตัดจากยอดในกระเป๋า ถ้าไม่พอ = `INSUFFICIENT_BALANCE` ไม่ตัดอะไรเลย (transaction เดียว) |
| ใครเห็นกระเป๋า | สมาชิกของแบรนด์นั้นเท่านั้น (RLS) · ไม่มีใครที่ล็อกอินอยู่เขียนกระเป๋าได้ — ฟังก์ชันเงินให้สิทธิ์แค่ `service_role` |

## ตาราง

- `wallet_accounts` — ยอดคงเหลือต่อแบรนด์
- `wallet_entries` — สมุดบัญชีแบบ append-only (`kind`: topup / purchase / refund / adjust) พร้อม `balance_after` ตรวจย้อนได้
- `wallet_topups` — ใบโอนแต่ละครั้ง + รูปสลิป (WebP) + ผลที่ EasySlip อ่านได้ + เหตุผลที่ยังไม่ผ่าน
- `wallet_orders` — สิ่งที่ซื้อจากกระเป๋า (แพ็กเกจรายเดือน / แพ็กข้อความ / แพ็กตรวจสลิป)
- `usage_counters` — ข้อความที่ส่ง และจำนวนครั้งตรวจสลิป ต่อแบรนด์ต่อเดือน (เดือนตามเวลาไทย)

## วิธีตั้งค่าก่อนใช้จริง

1. รัน `supabase/migrations/20261025003700_wallet.sql` ใน SQL Editor ของ booking-v2
2. `/super` → ตั้ง **บัญชีรับเงิน**: `billing.promptpay`, `billing.account_name`, `billing.bank` (3 ช่องนี้ใช้ตรวจว่าสลิปโอนเข้าบัญชีเรา)
3. `/super` → ตั้ง `slip.easyslip_api_key` (คีย์จาก developer.easyslip.com)
4. ทดสอบ: เปิด `/api/dashboard/brands/<brandId>/wallet` → เห็นยอด 0 และบัญชีรับเงิน

## API

| Method | Path | ทำอะไร |
|---|---|---|
| GET | `/api/dashboard/brands/<brandId>/wallet` | ยอด · แพ็กเกจ · โควตาที่ใช้ · รายการล่าสุด · ราคาแพ็ก |
| POST | `…/wallet/topups?amount=1000` | ส่งรูปสลิป (binary `image/jpeg|png|webp`) → เติมอัตโนมัติหรือรอตรวจ |
| POST | `…/wallet/orders` | `{ "sku": "plan:pro" }` → ตัดเงินและอัปเกรดแพ็กเกจ/เพิ่มโควตา |

## เรื่องที่ยังต้องตัดสินใจ / ยังไม่ทำ

1. **หน้าจอ** — ยังไม่มีหน้าจอกระเป๋าในแดชบอร์ด (API พร้อมแล้ว) — PR ถัดไป
2. **ผู้ดูแลอนุมัติใบที่ยัง pending** — ตอนนี้ใช้ SQL; ควรมีหน้า `/super` สำหรับอนุมัติ/ปฏิเสธ
3. **ภาษี** — เงินที่เติมเป็น "เงินล่วงหน้า" หรือ "รายได้" ต้องให้ accountant ยืนยัน (vat รับตอนเติมหรือตอนใช้) และต้องออกใบกำกับ/ใบเสร็จ
4. **บังคับเพดานโควตา** — เจ้าของยังไม่ต้องการบังคับ (เก็บตัวเลขไปก่อน) แต่ตาราง `usage_counters` เริ่มนับได้แล้ว
5. **คืนเงิน/ถอน** — ยังไม่มี; กระเป๋าไม่มีวันหมดอายุ (ต้องเขียนในข้อตกลง)
6. **EasySlip แพ็กเกจ** — ตอนนี้ใช้ Start 99 บาท/250 สลิป (0.396/ใบ) · ย้ายเป็น Basic 350/1,000 (0.35) เมื่อใช้เกิน 250/เดือน
