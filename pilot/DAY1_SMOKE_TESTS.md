# Pilot #1: Day-1 Smoke Test Scenarios

คู่มือการทดสอบระบบหน้างานจริงในวันเปิดตัว (Day-1 Smoke Tests) เพื่อยืนยันว่าฟังก์ชันสำคัญทั้งหมดของ **Luxe Hair & Beauty Studio** ทำงานได้อย่างถูกต้องและปลอดภัย

---

## สรุปรายการทดสอบ (Smoke Test Matrix)

| รหัส | รายการทดสอบ | ช่องทาง | ผลลัพธ์ที่คาดหวัง |
| :---: | :--- | :---: | :--- |
| **ST-01** | จองบริการผ่านหน้าเว็บ (Customer Web Booking) | Web (`/`) | จองสำเร็จ, สร้าง Booking ID, ได้รับสถานะ Confirmed |
| **ST-02** | ป้องกันการจองคิวซ้อน (Double-Booking Rejection) | Web (`/`) | ไม่อนุญาตให้จองเวลาชนกับคิวเดิม, แจ้งเตือนภาษาไทยสุภาพ |
| **ST-03** | ยืนยันตัวตนจัดการนัดหมาย (Phone Verification Gate) | Web (`/manage/[id]`) | ปฏิเสธการเข้าถึงด้วย UUID เพียงอย่างเดียว, ต้องใส่เบอร์โทรตรง |
| **ST-04** | เลื่อนวัน/เวลานัดหมาย (Reschedule Flow) | Web (`/manage/[id]`) | อัปเดตเวลาใหม่สำเร็จ, ยกเลิก Reminder เดิม, ตารางใหม่พร้อม |
| **ST-05** | ยกเลิกนัดหมายตามเงื่อนไข (Cancellation Policy Gate) | Web (`/manage/[id]`) | ยกเลิกได้หากล่วงหน้าเกิน 24 ชม., คืนสล็อตเวลาให้ว่าง |
| **ST-06** | จองผ่าน AI Receptionist (Safe Tool Booking) | Web (`/assistant`) | ดึงเวลาว่างจริง, แสดงการทบทวน (Review), ต้องกดยืนยันจึงจะจอง |
| **ST-07** | ส่งต่อเคสให้พนักงาน (Human Handoff Escalation) | Web (`/assistant`) | ขอส่วนลด/ร้องเรียน ระบบสร้าง Handoff Request และแจ้งเบอร์ร้าน |
| **ST-08** | ระบบหลังบ้านและตัวรันอัตโนมัติ (Admin & Runner) | Admin / CLI | Admin ดูรายการจองและเคส Handoff ได้, Runner ประมวลผลสำเร็จ |

---

## ขั้นตอนการทดสอบอย่างละเอียด

### ST-01: การจองบริการผ่านหน้าเว็บ (`/`)
1. เข้าไปที่หน้าแรกของร้าน: `https://your-domain.example/`
2. เลือกบริการ: **"ตัดผมและจัดทรง"**
3. เลือกช่าง: **"ช่างแอน"**
4. เลือกวันที่: วันพรุ่งนี้
5. เลือกรอบเวลาที่ระบบแสดง (เช่น 10:00 - 11:00)
6. ระบุข้อมูลลูกค้า:
   - ชื่อ: `สมชาย ทดสอบระบบ`
   - เบอร์โทรศัพท์: `0891234567`
7. ตรวจสอบสรุปข้อมูลและกดปุ่ม **"ยืนยันการจอง"**
8. **ผลที่ต้องเกิดขึ้น**:
   - หน้าจอแสดงรหัสการจอง (UUID) และสถานะ `confirmed`
   - มีปุ่มสำหรับไปยังหน้า "จัดการนัดหมาย"

---

### ST-02: ป้องกันการจองคิวซ้อน (Double-Booking Prevention)
1. เปิดหน้าจองในอีกหน้าต่าง (Incognito หรืออุปกรณ์อื่น)
2. เลือกบริการ ช่างแอน และวันที่/เวลาเดียวกันกับ ST-01
3. กรอกชื่อลูกค้าอื่น (เช่น `สมหญิง ทดสอบซ้อน`, `0899887766`)
4. พยายามกดปุ่มยืนยันการจอง
5. **ผลที่ต้องเกิดขึ้น**:
   - ระบบปฏิเสธการจองทันที
   - แสดงข้อความเตือนภาษาไทยชัดเจน (เช่น *"ช่วงเวลานี้มีคิวจองแล้ว กรุณาเลือกเวลาอื่น"*)
   - ตรวจสอบในฐานข้อมูลว่าไม่มีแถวข้อมูลจองซ้อนถูกเพิ่มเข้าไป

---

### ST-03: การยืนยันสิทธิ์จัดการนัดหมาย (`/manage/[id]`)
1. เข้า URL นัดหมายโดยตรง: `https://your-domain.example/manage/<booking-id-จาก-ST-01>`
2. **ผลที่ต้องเกิดขึ้น**:
   - หน้าเว็บต้องแสดงกล่องให้กรอก **"เบอร์โทรที่ใช้จอง"** ก่อนเสมอ
   - ยังไม่แสดงชื่อ รายละเอียดบริการ หรือเบอร์โทรของลูกค้า
3. ลองกรอกเบอร์โทรที่ไม่ตรง (เช่น `0811111111`) แล้วกดส่ง -> ระบบต้องปฏิเสธ
4. กรอกเบอร์โทรที่ถูกต้อง (`0891234567`) แล้วกดยืนยัน
5. **ผลที่ต้องเกิดขึ้น**: ข้อมูลนัดหมายแสดงขึ้นมาอย่างครบถ้วน

---

### ST-04: การเลื่อนนัดหมาย (Reschedule Flow)
1. ในหน้า Manage Booking ที่ยืนยันเบอร์โทรแล้ว ให้คลิก **"เลื่อนเวลานัดหมาย"**
2. เลือกรอบเวลาว่างใหม่ที่ยังไม่มีใครจอง (เช่น 14:00 - 15:00)
3. กดยืนยันการเลื่อนนัด
4. **ผลที่ต้องเกิดขึ้น**:
   - เวลานัดหมายของ Booking เปลี่ยนเป็นรอบเวลาใหม่
   - มีการบันทึกประวัติลง `booking_status_history`
   - Job แจ้งเตือน (Reminder) ของเวลาเดิมถูก Cancelled และมี Job ใหม่ถูกสร้างขึ้น

---

### ST-05: การยกเลิกนัดหมายตาม Policy
1. ในหน้า Manage Booking ให้คลิก **"ยกเลิกนัดหมาย"**
2. ระบุเหตุผล (เช่น `ติดธุระด่วน`)
3. กดยืนยันการยกเลิก
4. **ผลที่ต้องเกิดขึ้น**:
   - หากเวลาปัจจุบันห่างจากเวลานัดมากกว่า 24 ชั่วโมง (`CANCELLATION_WINDOW_HOURS`): สถานะเปลี่ยนเป็น `cancelled` สำเร็จ
   - เวลานัดเดิมของช่างจะกลับมาเป็นสล็อตว่างพร้อมให้ผู้อื่นจองได้อีกครั้ง

---

### ST-06: การจองผ่าน AI Receptionist (`/assistant`)
1. เปิดหน้า `https://your-domain.example/assistant`
2. พิมพ์สอบถาม: *"พรุ่งนี้มีคิวตัดผมกับช่างมีนไหมครับ"*
3. ตรวจสอบว่าระบบเรียกเครื่องมือ `check_availability` และแสดงเฉพาะเวลาที่ว่างจริง
4. เลือกช่วงเวลาที่ต้องการ
5. พิมพ์ชื่อและเบอร์โทร: `ทดสอบ เอไอ 0812345678`
6. **ตรวจสอบความปลอดภัย (Critical Check)**:
   - ระบบต้องแสดงกล่อง **"ตรวจสอบนัดหมาย" (Review)** ก่อน
   - ในขั้นตอนนี้ต้อง **ยังไม่มีการสร้าง Booking ในระบบจริง**
7. คลิกปุ่ม **"ยืนยัน"** ในข้อความถัดไป
8. **ผลที่ต้องเกิดขึ้น**: ระบบส่งคำขอยืนยัน บันทึก Booking ลงฐานข้อมูล และแสดงการ์ดรายการสำเร็จพร้อม Reference ID

---

### ST-07: การส่งต่อเคสให้พนักงาน (Human Handoff)
1. ในหน้า `/assistant` ให้พิมพ์: *"ขอลดราคา 50% ได้ไหมครับ"* หรือคลิก *"ติดต่อพนักงาน"*
2. **ผลที่ต้องเกิดขึ้น**:
   - AI ตอบกลับอย่างสุภาพว่าไม่สามารถอนุมัติส่วนลดพิเศษได้เอง
   - แสดงข้อความและเบอร์โทรติดต่อผู้จัดการร้านตามที่ตั้งไว้ใน `HANDOFF_DESTINATION`
   - มีแถวข้อมูลบันทึกลงในตาราง `handoff_requests` ด้วยสถานะ `pending`

---

### ST-08: ตรวจสอบ Admin Dashboard และ Automation Worker
1. เข้าหน้า `https://your-domain.example/admin`
2. ป้อนรหัสผ่านผู้ดูแลระบบที่กำหนดไว้
3. ตรวจสอบตารางนัดหมายของวันนี้และแท็บรายการ Handoff Requests
4. ทดสอบสั่งประมวลผล Automation:
   ```bash
   npm run automation:run
   ```
   หรือยิง HTTP POST ไปที่ `/api/internal/automation/run` พร้อม Bearer token
5. **ผลที่ต้องเกิดขึ้น**:
   - Worker ประมวลผลเรียบร้อยและคืนค่า JSON สรุปจำนวน Jobs ที่สำเร็จ
   - ไม่มี Job ตกค้างในสถานะ `processing` นานเกิน 5 นาที
